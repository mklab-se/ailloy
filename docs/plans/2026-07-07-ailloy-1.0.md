# Ailloy 1.0.0 — Provider Currency, Eval, Config & Security

> Executed inline (superpowers:executing-plans). Scope approved by Kristofer 2026-07-07:
> batches A (provider currency), B (eval + JSON output), C (config & security);
> tool calling deferred to a documented proposal. Ships as **1.0.0**.

**Goal:** Bring ailloy current with July-2026 provider APIs, add the eval/JSON
capabilities its script use-case needs, harden config (keychain, programmatic
API), and release 1.0.0.

**Research base:** Azure's unified `/openai/v1/` surface is GA (no dated
api-version; model = deployment name; same surface on
`{account}.services.ai.azure.com` serves Foundry partner models). GPT-5.x /
newest Claude / Gemini 3 reject non-default sampling params. `gpt-4o` retires
2026-10-01, `gpt-4.1` family 2026-10-14.

## Global constraints
- Library API additions must be backward compatible in spirit (1.0.0 may break,
  but dependents rigg/cosq/mdeck/pidge are updated in the same effort).
- Gates: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`
  (and `--no-default-features --lib`), `cargo test`.
- No secrets in repo; keychain optional at runtime, never required.

## Task A1 — Azure + Foundry on the unified v1 surface
- `azure.rs`: when the node has NO explicit `api_version`, use
  `{endpoint}/openai/v1/{chat/completions|embeddings|images/generations}` with
  `"model": {deployment}` in the body. When `api_version` IS set, keep the
  legacy dated `/openai/deployments/{d}/...?api-version=` path (escape hatch).
- `foundry.rs`: same rule — v1 path `{endpoint}/openai/v1/chat/completions`
  (endpoint already normalized to `services.ai.azure.com`); dated
  `/models/chat/completions?api-version=` only when configured.
- `client.rs`: stop injecting the default api-versions (2025-04-01-preview /
  2024-05-01-preview); pass None unless the node sets one.
- Tests: URL construction for both styles; body carries model on v1.

## Task A2 — Sampling guards (retry-on-400)
- Shared helper: on HTTP 400 whose body names `temperature`/`top_p`
  (`unsupported`/`does not support`), retry once with those options dropped and
  log a debug note. Apply in openai/azure/foundry/anthropic/vertex chat paths.
- Test: mocked 400-then-200 (unit-level on the decision helper).

## Task A3 — Token caps, default models, retirement warnings
- Anthropic default `max_tokens` 4096 → 8192 (opts still win).
- Defaults: `gpt-4o` → `gpt-5.4-mini` everywhere (client.rs, config_tui.rs,
  config.rs, discover); anthropic → `claude-sonnet-5` (was 4-6);
  vertex stays `gemini-3.1-pro`.
- Static retirement table (model prefix → date) checked by `ai status`:
  warn for configured node models at/near retirement (gpt-4o, gpt-4.1*,
  o1*/o3-mini/o4-mini, claude-opus-4-1, claude-3-*).

## Task A4 — Streaming usage
- OpenAI-family: send `stream_options: {"include_usage": true}`; surface the
  final usage chunk in `StreamEvent::Done`.
- Anthropic: accumulate `message_start`/`message_delta` usage into Done.

## Task B1 — `ChatOptions.response_format`
- `types.rs`: `pub enum ResponseFormat { JsonObject, JsonSchema { name: String, schema: serde_json::Value, strict: bool } }`,
  `ChatOptions.response_format: Option<ResponseFormat>` (+ builder method).
- Wire: OpenAI/Azure/Foundry `response_format` (json_object / json_schema);
  Anthropic `output_config.format`; Vertex `generationConfig.responseMimeType`
  + `responseSchema`; Ollama `format: "json"`/schema.
- Tests: request-body serialization per provider.

## Task B2 — `ailloy eval`
- New `commands/eval.rs` + CLI:
  `ailloy eval --criteria "<text>" [--criteria-file f] [INPUT] [--file f]
   [--context c] [--node n] [--output text|json] [--threshold 0.0-1.0]`
- Input precedence: arg, --file, stdin. Judge prompt asks for strict JSON
  `{pass: bool, score: 0..1, reasons: [string]}` via response_format
  (JsonSchema); threshold (default: pass field) overrides with score >= t.
- Exit codes: **0 pass, 1 fail, 2 usage/config error, 3 provider error**.
- `--output json` prints the verdict object verbatim; text prints PASS/FAIL,
  score, bulleted reasons.
- Tests: verdict parsing, exit-code mapping, prompt construction.

## Task B3 — `ailloy chat --json [--schema <file>]`
- `--json` sets ResponseFormat::JsonObject (and instructs via system nudge if
  provider lacks it); `--schema file.json` sets JsonSchema (strict).
- Output is the raw model JSON (no banner/decoration), so scripts can pipe.

## Task C1 — Keychain auth
- Dep `keyring = "3"` behind new default-on feature `keychain` (lib-usable).
- `Auth::Keychain` variant: secret stored under service `ailloy`,
  account `{node_id}`. `config.rs` resolve_api_key falls through:
  Keychain → keyring lookup with clear error incl. how to set.
- TUI: "Store in OS keychain" option when entering a key;
  `ailloy ai config set-key <node>` prompts (hidden input) and stores.
- Tests: mock via trait? keyring has a mock feature — use `keyring` mock store
  in tests.

## Task C2 — Programmatic config API (for dependent tools)
- `config.rs` additions (documented, doctested):
  `Config::ensure_node(id, AiNode) -> bool` (insert-if-absent),
  `Config::upsert_node(id, AiNode)`, `Config::remove_node(id)`,
  `Config::set_default_for(capability, node_id) -> Result`,
  `Config::set_keychain_secret(node_id, secret)` (feature-gated),
  plus existing load/save round-trip documented as THE embedding pattern.
- README section "Configuring ailloy from your tool" with a rigg-style example.

## Task C3 — `ailloy ai test --all`

  1-token "ping" chat, embed-capable a 1-string embed; table of ✓/✗ + latency;
  exit 1 if any fail. Single-node behavior unchanged.
