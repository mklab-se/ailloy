# ailloy 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved spec `docs/superpowers/specs/2026-07-15-image-video-multimodal-tui-design.md` — Foundry image support (gpt-image-2), the full image parameter surface incl. reference images, sora-2 video generation, multimodal chat attachments, capability-scoped per-node defaults, and a ratatui config TUI — released as ailloy 2.0.0.

**Architecture:** Extend the existing feature-flagged single crate. New capability `video` flows through the existing `ProviderKind::supports_task` → `Capability` → `defaults` routing. Shared internal request-builder modules (`openai_images.rs`, `video_jobs.rs`) keep OpenAI/Azure/Foundry image+video wire code DRY. `Message.content` becomes an untagged `MessageContent` enum so plain strings round-trip unchanged. A static parameter registry (`params.rs`) is the single source of truth for per-node defaults, CLI validation, and the new ratatui dashboard.

**Tech Stack:** Rust edition 2024 (MSRV 1.86), tokio, reqwest (+`multipart` feature), serde, ratatui (new, behind `config-tui`), crossterm, clap.

## Global Constraints

- `cargo clippy -- -D warnings` and `cargo fmt --all -- --check` must pass after every task (zero-warnings policy).
- `cargo build --no-default-features --lib` must keep compiling after every task (library-only build).
- All error messages actionable: what failed, which resource/node, what to do next.
- All config maps stay `BTreeMap`. Node IDs stay `{provider}/{model|deployment|binary}`.
- Azure/Foundry endpoint rule preserved: no `api_version` on node → unified `/openai/v1/` surface; explicit `api_version` → legacy dated endpoints. Video jobs on the v1 surface always append `?api-version=preview`.
- Version target: 2.0.0. Deprecated 1.x APIs keep compiling with `#[deprecated(since = "2.0.0", note = "...")]`.
- Commit after every green task; conventional-commit style messages.

```rust
#[serde(untagged)]
pub enum MessageContent { Text(String), Parts(Vec<ContentPart>) }

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "lowercase")]
pub enum ContentPart {
    Text { text: String },
    Image { #[serde(with = "crate::types::base64_bytes")] data: Vec<u8>, media_type: String },
    File  { #[serde(with = "crate::types::base64_bytes")] data: Vec<u8>, media_type: String, filename: String },
}
// mod base64_bytes: serialize/deserialize Vec<u8> ⇄ base64 String.
impl MessageContent {
    pub fn text(&self) -> String;            // Text → clone; Parts → text parts joined "\n"
    pub fn as_text(&self) -> Option<&str>;   // Some only for Text
    pub fn has_attachments(&self) -> bool;
}
impl From<String> for MessageContent; impl From<&str> for MessageContent;
impl std::fmt::Display for MessageContent;  // = self.text()
// Message constructors become impl Into<MessageContent>;
pub fn user_with_attachments(text: impl Into<String>, files: &[std::path::PathBuf]) -> anyhow::Result<Message>;
// media type inference by extension: png/jpg/jpeg/gif/webp → Image part;
// pdf → File "application/pdf"; txt/md/csv/json/yaml/xml/html and unknown-but-utf8 → File "text/plain"-family;
// other binary → error "unsupported attachment type <ext> — supported: images, pdf, text files".
```
Internal migration: everywhere that read `msg.content` as a String uses `msg.content.text()` (display, history, eval prompts) or `as_text()`. Provider wire code is Task 3.2; until then providers may call `.text()` to stay green.
